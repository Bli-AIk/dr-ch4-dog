# 第 04 集：创建项目与进入第一场战斗

欢迎回来！这是《从零做一个 Deltarune 同人游戏》系列的第 4 集，也是**第一章的第一集**——从这一集开始，我们真的动手了。

第 03 集那份目标清单还记着吧？清单第一行写着"项目能跑起来"。本集要做的，就是让这一行打上勾：把模板正式变成我们的项目，逛一圈它自带的世界，然后——进入第一场战斗。

第一章的玩法也预告一下：每一集都以一个能跑的结果收尾（清单上的一行），你可以随时停下、随时继续——项目永远是"上一次做的东西还能跑"的状态。

## 创建课程项目

先回顾一下手上有什么（第 01 集做的）：LÖVE 装好了、Kristal 引擎克隆好了、thrash-machine 模板也通过 use this template 建出来了——当时我们跑了 `./start.sh`，现在说说它到底干了什么：

1. 把模板里的项目名、Mod ID 全部替换成你的项目名（比如 `my-first-kristal-game`）；
2. 把相关的文件名、构建配置同步改名；
3. 拉齐所有子模块（`libraries/` 里的库）。

跑完之后，模板就"变成你的项目"了——名字是你的、ID 是你的、Git 历史也是从你的仓库开始的。

start.sh 还有两个实用参数：`./start.sh --name "我的项目"`（直接指定名字，不用交互输入）、`./start.sh --yes`（用当前目录名直接跑，适合非交互环境）。名字可以随时再改，别在起名上卡太久。

打开 `mod.json` 看看，项目的重要信息都在这：

```json
"id": "thrash-machine",      // 项目的唯一 ID
"name": "Thrash Machine",    // 主菜单显示的名字
"map": "room1",              // 启动时进入的地图
"party": ["kris", "susie", "ralsei"],  // 队伍
```

（如果你还没跑 start.sh 或者想改名，现在跑/重跑一次都来得及——后面的内容不依赖具体名字。）

## 三百六十度转一圈

项目建好了，先别急着改代码——**把 Kristal 自带的东西逛一遍**。启动引擎（第 01 集的 `love .` 或在引擎目录跑），从项目列表打开你的项目。

你会落到一张地图上（`room1`）。这张小地图上藏着 Kristal 世界系统的几个基本元素，顺带把名词带一遍：

- **地图（map）**：你现在站的地方。Kristal 的地图由图层（tiles 地面、decal 装饰、collision 碰撞、objects 物体）组成；
- **事件（event）**：地图上"能互动的东西"。这个房间里有一个**存档点**（星星）——存档点是 Interactable（可交互对象）的一种，调查它就能存档、回血；
- **往下走**，能看到一个**星之行者**——它也是事件，靠近它会触发对话（这就是文本事件）；
- **调查墙上的裂缝**，会触发一段过场动画（cutscene）——"墙裂了，苏西想试试能不能打破"；
- **往右走**，切换到 `room2`——房间里有个训练人偶（dummy），靠近它，会进入一场**战斗**。

真进了战斗，第一印象是经典的 Deltarune 布局：你的**灵魂**（红色心形）在**战斗框**（下方区域）里移动，敌人站在上方，下方是四个选项——这就是所有后续战斗的舞台，我们后面做的每一场战斗，都是在这个布局上添东西。

> 📷 此处插入截图：room1 地图（标注存档点、星之行者、墙）

切换房间是怎么发生的？room1 和 room2 之间有个**过渡（transition）**——走到地图边缘，画面切换，你就到了下一张地图。这个机制第二章会细讲，现在先记住"地图之间靠过渡连接"。

存档点的交互也值得仔细试一下：靠近星星按确认键，会弹出存档菜单（存档/储物/队伍管理）——这是战斗之外的另一个完整系统。

逛这一圈，其实已经把 Kristal 世界的四大块都摸到了：**地图、事件、过场、战斗**。第二章我们做地图时，会再回来一个一个细讲——现在先混个脸熟。

## 进入第一场战斗

刚才是"靠近人偶进战斗"——但我们的目标清单要的是"启动直接进战斗"。Kristal 支持这个：在 `mod.json` 里加一行：

```json
"encounter": "dummy",
```

（加在 `mod.json` 的顶层，和其他字段平级——这是 Kristal 开发模式的入口配置，下一集做神烦狗遭遇战时，把它改成 `"encounter": "dog"` 就行。）

保存，重新启动项目——游戏会跳过地图，直接进入和训练人偶的战斗。这就是我们的"第一场战斗"：一个能打、能 ACT、能饶恕的完整教学战斗。

进去之后，战斗界面的四个选项值得每个都试一遍：

- **FIGHT**：攻击——打训练人偶；
- **ACT**：互动——人偶有"微笑""讲故事"两个 ACT（下一集我们会给狗做这些）；
- **ITEM**：物品——用道具；
- **MERCY**：饶恕——攒够饶恕值可以放走它。

这四个选项就是 Deltarune 战斗的全部交互方式，也是后面所有敌人设计的骨架。

> 📷 此处插入截图：启动直接进入 dummy 战斗

另外介绍一个开发利器：`just`。thrash-machine 自带了一个调试启动器（kristal-debug-tools），在项目目录里运行：

```bash
just run
```

它和 `love .` 的效果类似（自动找到引擎、自动启动你的项目），但多了调试参数：

```bash
just run --encounter dummy    # 直接进指定战斗
just run --wave 2             # 指定回合
just run --tp 50              # 初始 TP
just run --mercy 100          # 初始饶恕值
```

后面每一集调试战斗，都会用到它——现在先记住 `just run --encounter` 能让任何战斗秒进，调试效率直接起飞。举个实际的例子：下一集我们做完神烦狗的遭遇战，想直接测它，只需要 `just run --encounter dog`——不用从主菜单点来点去，战斗秒进。

## 认识项目目录

战斗进来了，看看它是怎么被组织起来的。打开 `scripts/battle/`（第 02 集目录树里的战斗目录），dummy 战斗由这几个文件组成：

- `enemies/dummy.lua`：**敌人**——训练人偶的定义（血量、攻击、ACT 选项）；
- `encounters/dummy.lua`：**遭遇战**——战斗的"容器"（敌人是谁、开场说什么、回合怎么流转）；
- `waves/basic.lua`：**弹幕回合**——敌人攻击期的内容；
- `cutscenes/dummy.lua`：战斗演出（ACT 触发的小剧情）；
- `data/actors/dummy.lua`：角色的**形象数据**（长什么样、动画怎么播）。

注意它们之间的连接方式：`mod.json` 的 `encounter` 字段说"进 dummy 遭遇战"→ `encounters/dummy.lua` 说"敌人是 dummy"→ `enemies/dummy.lua` 说"回合用 basic"→ `waves/basic.lua` 说"弹幕怎么放"。一层指一层，**ID 是连接它们的胶水**——这正是第 00 集说的"模组是可以带库的"同款机制：约定好 ID，引擎自动把它们拼起来。

除了 `scripts/battle/`，项目里还有：`scripts/world/`（地图和过场——room1/room2 就在这）、`scripts/data/`（角色形象数据）、`assets/`（素材）、`lang/`（文本）、`libraries/`（库）。dummy 战斗只用了 `battle/` 和 `data/` 的一小部分，其他目录第二章才会全面用到——先知道它们存在就行。

随便挑一个文件打开看看——`scripts/battle/enemies/dummy.lua` 的开头：

```lua
local Dummy, super = Class(EnemyBattler)

function Dummy:init()
    super.init(self)
    self:applyLocalization()
    self:setActor("dummy")

    self.max_health = 450
    self.health = 450
    self.attack = 4
    self.defense = 0
    self.money = 100
end
```

眼熟吗？EX01（Lua 速通）里我们逐行读过这种写法——`Class(EnemyBattler)` 继承、`init` 里设数值、`self` 挂属性。速通学的，在这里全用上了。

dummy 的完整结构（enemy → encounter → wave → cutscene）其实就是接下来几集的路线图：下一集把 dummy 换成狗（敌人 + 遭遇战 + ACT），再往后三集分别做三个回合的 wave——你已经知道文件放哪、怎么串了。

## 检查本集成果

对照第 03 集的目标清单，第一行"项目能跑起来"——打勾。完整链路现在是：

```text
love . → 引擎加载 mod → mod.json 指定 encounter → 遭遇战指定敌人 → 敌人指定回合 → 战斗开始
```

顺手把清单完整过一遍：项目能跑 ✓；敌人能出现在战斗里——dummy 算半个（它是模板自带的，下一集换成神烦狗）；ACT 菜单、三个回合、胜负流程……都排在后面。每加一个环节，都看得见、可验证（第 02 集的原则）——这就是第一章开工的正确姿势。

这条链路会贯穿整个第一章：后面每做一块，都是在这条链上加一环——加敌人、加 ACT、加回合、加胜负，最后链子完整了，战斗就完整了。
