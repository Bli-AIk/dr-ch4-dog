# 第 03 集：如何拆解一个 Deltarune 同人游戏（Dog Battle 项目规划）

你好呀。这是《从零做一个 Deltarune 同人游戏》系列的第 3 集。

第 02 集我们学会了查资料，这一集就要开始用：把 Dog Battle 这个"想法"，拆成一份能照着开工的计划。序章到这里就结束了——下一集开始，我们真的动手。

## 从想法到计划

第 00 集我们描述过最终成品：一只打不死的狗、三个回合、一场完整的战斗、饶恕才能赢。但"描述"和"能开工"之间，隔着一段路——这段路就是**规划**。

描述说的是"它是什么"，规划回答的是"它由哪些部分组成、按什么顺序做出来"。没有规划的开发，就像没有地图的探索：走一步看一步，走着走着就不知道自己做到哪了，也不知道什么时候算做完。

规划的起点，不是功能列表，而是玩家体验。

## 从玩家体验开始拆解

先想清楚：**玩家会经历什么？** 把这场战斗从头到尾在脑子里过一遍：

进入战斗 → 看到对面的神烦狗 → 打开 ACT 菜单（查看、摸狗、讲笑话）→ 攻击它，被闪避，金色 MISS → 第一回合弹幕 → 第二回合演出 → 第三回合冲撞 → 中间还要试试摸狗（失败）和讲笑话 → 最后队伍版摸狗，狗被饶恕，战斗结束。

而我们的 Dog Battle 有个现成的锚点——**原动画**。它把这段体验完整演过一遍，时间轴就是最好的结构参考：

| 时间 | 内容 |
| --- | --- |
| 0:00-0:23 | 开头 ow（地图） |
| 0:23-0:35 | 敌人回合前：基础 ACT 和旁白 |
| 0:35-0:44 | 第一回合 |
| 0:44-0:52 | 摸狗失败 |
| 0:52-1:00 | 第二回合 |
| 1:00-1:15 | 苏西反应 + 讲笑话 |
| 1:15-1:26 | 摸狗 + 饶恕 |

这个时间轴就是战斗的目标体验骨架：开头 ow（这个第二章再做）→ 敌人回合前的旁白和 ACT → 第一回合 → 摸狗失败 → 第二回合 → 苏西反应 + 讲笑话 → 摸狗 + 饶恕 → 片尾。第一章要做的，就是中间"敌人回合前 → 饶恕"这一整段。

（诚实声明：这是**参考结构**，不是逐帧复刻。第 00 集说过，我们做的时候没有对着原视频对轴——先求结构对得上，节奏和细节后面再调。）

## 拆分游戏流程

整个游戏的流程，可以分成五个阶段：**启动 → 地图 → 剧情 → 战斗 → 结束**。这是所有 Deltarune 同人游戏共同的骨架。

但我们不打算一次全做。第一章只做**战斗闭环**——对应时间轴上"敌人回合前 → 饶恕"的部分；开头和片尾的 ow、剧情，全部留给第二章。原因很简单：战斗是 Dog Battle 的核心，先把核心做成完整体验，比什么都有说服力。

拆流程还有个附带的好处：每个阶段之间的"接口"会自然浮现——比如"地图怎么进入战斗"（第二章的事）和"战斗怎么结束回到地图"（第一章尾声就要留好口子）。

## 拆分战斗内容

流程拆完，再把战斗本身拆开。这一步可以直接用第 00 集的"项目事实"——当时是描述，现在是任务清单：

- **敌人（神烦狗）**：数值（450 HP、攻击 4）、行为（伤害恒为 0、被攻击时转圈 + 金色 MISS）、演出（待机动画、被摸的反应）；
- **Encounter**：战斗的"容器"——决定敌人是谁、战斗开始时的旁白、回合怎么流转；
- **ACT**：查看、摸狗（单人/队伍版）、讲笑话——每个选项的触发逻辑和文本；
- **回合**：三个 wave（骨头、GB、车），固定顺序，每个 wave 有自己的生成逻辑和演出；
- **胜负状态**：胜利 = 讲笑话后队伍版摸狗 → 饶恕；失败 = 标准失败流程；
- **文本**：所有对话、ACT 名称、检查信息——中英双语（kristal-i18n）。

这一拆，第一章的工作范围就清楚了：六块，一块不多。

## 确定 Dog Battle 的特色

规划里必须有一件事：**这个项目最该让人记住的是什么？** 不然做着做着，就会变成"又一个什么都有点但都没特点的同人战斗"。

Dog Battle 的特色，我们认为有两条：

1. **演出**。三个回合的编排感——第一回合的经典骨头，第二回合的蓄力（转圈、发光、吸收粒子）和 GB 炮，第三回合的撞击（镜头震动、爆炸）。动画里那种"一段一段有起伏"的节奏，是战斗的灵魂。
2. **狗的角色性**。打不死的狗（金色 MISS）、摸狗失败、讲笑话的彩蛋、最后"讲完笑话再去摸它"才饶恕的仪式感——玩家记住的不是"打了三回合"，而是"和这只狗发生了一段故事"。

特色决定优先级：**先保证演出能跑通，再谈打磨**。弹幕密度可以调，数值可以调，但"演出有没有"是一票否决的。

## 安排制作顺序

拆出来的六块，不是随便哪个先做——它们之间有依赖关系：

1. **项目能跑起来**（这是地基，第 05 集）；
2. **敌人能出现在战斗里**——Enemy 和 Encounter 的最小形态（第 06 集）；
3. **ACT 菜单**——有了菜单，玩家才有"互动"的手段（第 06 集后半）；
4. **第一回合**：骨头弹幕（第 07 集）——第一回合跑通，说明"弹幕"这条最核心的链路通了；
5. **第二回合**：GB 演出 + 苏西反应（第 08 集）；
6. **第三回合**：车冲撞（第 09 集）；
7. **胜负与对话**：饶恕、失败、战斗旁白全部接上（第 10 集）；
8. **测试打磨**：难度、节奏、稳定性（第 11 集）；
9. **发布**（第 12 集）。

每一步做完，游戏都是**可运行、可验证**的——这正是第 02 集说的：做完一步，跑起来看一眼，对了再下一步。

## 控制项目范围：第一章目标清单

规划最容易犯的错是贪多。把"必须做"和"以后再说"分开，第一章的目标清单长这样：

**必须做（第一章）**

- 神烦狗敌人：数值、不吃伤害、金色 MISS 演出
- Encounter：战斗容器 + 开场旁白
- ACT：查看 / 摸狗（单人+队伍版）/ 讲笑话
- 摸狗失败演出（时间轴 0:44-0:52）
- 三个回合：骨头 / GB（含苏西反应）/ 车
- 饶恕胜利路径（讲笑话 → 队伍版摸狗 → 饶恕）
- 失败流程 + 战斗对话
- 中英双语文本

**砍掉，留到以后**

- 开头 / 片尾的 ow（第二章）
- 剧情 cutscene（第二章）
- 商店、更多敌人、Boss 战（第三章/第四章）

> 📷 此处插入截图：目标清单示意图（可勾选清单）

这份清单不是摆设——它是给后面每一集打勾用的。每做完一集，回来看一眼清单，进度一目了然。这也是第 02 集说的"记录"习惯：把计划记下来，比记在脑子里可靠。

另外给规划泼盆冷水：这份清单是"够用就行"的版本，不是"完美计划"。规划的目的是让你不迷路，不是让你把每个细节都定死——真做起来，发现哪块比想象难，砍掉它、调整它，都很正常。计划是地图，不是镣铐。

## 形成课程路线

最后，把清单和课程对应起来。你会发现第一章的每一集，正好就是在清单上填一块：

- 第 05 集：项目创建与进入战斗（清单第 1 行：项目能跑）
- 第 06 集：敌人、Encounter 与 ACT 菜单
- 第 07 集：第一回合（骨头）
- 第 08 集：第二回合（GB + 苏西反应）
- 第 09 集：第三回合（车）
- 第 10 集：战斗收尾（胜负、对话、完整流程）
- 第 11 集：测试、Debug 与迭代
- 第 12 集：打包发布

八集，八块拼图，拼完就是一份完整的第一章。

## 结尾

规划做完了：体验有锚（动画时间轴）、结构有拆（六块内容）、顺序有依赖（八步链条）、范围有界（目标清单）。序章的三件套——环境、查资料、规划——到此全部齐了，这就是动手之前该有的全部准备。
