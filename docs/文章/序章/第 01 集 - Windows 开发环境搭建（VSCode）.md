# 第 01 集：Windows 开发环境搭建（VSCode）

> 本系列的第 2 篇。这一篇没有代码，我们要做的是把地基打好：让 LÖVE、Kristal 和你的第一个项目，在 Windows 上全部跑起来。

## 先说清楚

你用的系统是 Windows，对吧？好，这篇就是为你准备的（Linux 和 Android Termux 的读者，请移步第 02 集番外）。

本集结束时，你会拥有一个可以运行的开发环境：一个命令行就能启动的 LÖVE 和 Kristal，一个能在项目列表里点开的游戏，以及一个配置好的 VSCode。之后每一集，我们都在这个环境上开工。

> 📷 此处插入截图：配置完成后的开发工作区

## 要准备的工具

其实没几样。整个开发链只有四个东西：

- **Git**：用来下载 Kristal 源码和项目模板。装好就行，这个系列里你只需要会用 `git clone`（更多 Git 知识可以看番外 EX03）。
- **LÖVE 11.5**：Kristal 的运行时——就是第 00 集说的那块"地基"。游戏最终就是靠它跑起来的。
- **Kristal 源码**：引擎本体。开发同人游戏要用源码版，为什么下面会说。
- **VSCode**：代码编辑器。官方 wiki 里也明确推荐用它，而且 Kristal 有官方扩展，后面会装。

## 安装 LÖVE，并配置环境变量

先去 [love2d.org](https://love2d.org/) 下载 Windows 安装包，一路下一步装完。默认位置是 `C:\Program Files\LOVE\`。

装完先别急着用。LÖVE 的 Windows 安装包**不会**自动把程序目录加进 PATH——也就是说，你在命令行里输入 `love`，系统根本不知道你在说什么。这一步要手动来：

1. 按 `Win` 键，搜索"编辑环境变量"，打开（控制面板里的"系统属性 → 环境变量"也行）。
2. 在"用户变量"里找到 `Path`，双击编辑。
3. 点"新建"，填入 `C:\Program Files\LOVE`，一路确定保存。
4. **新开一个** cmd 窗口（旧窗口不会刷新 PATH），输入：

```cmd
love --version
```

能看到返回 `11.5` 这样的版本号，就说明成了。这一步很重要，因为后面所有的启动命令都是 `love .`——如果 PATH 没配好，这个命令就永远跑不起来。

## 配置 Kristal：为什么是源码版

官方 wiki 把 Kristal 的获取方式分成三种：

- **公开测试版（Beta）**：官方不推荐。更新太慢，容易过时。
- **每日构建版（Nightly）**：推荐给**玩**同人游戏的玩家，每次代码变更都会重新构建，最新但未经测试。
- **源代码**：推荐给**做**同人游戏的开发者。最麻烦，但可控性最强，以后想改引擎、想参与开发都靠它。

我们要做游戏，所以用第三种。在你想放引擎的目录打开终端：

```cmd
git clone https://github.com/KristalTeam/Kristal
```

然后进入目录，运行：

```cmd
cd Kristal
love .
```

Kristal 主菜单应该就出现了。第一次看到它，可以随便逛逛——在主菜单里找到项目列表的入口（不同版本入口位置可能不太一样），点进去，你会看到一个项目列表。

> 📷 此处插入截图：Kristal 主菜单 / 项目列表界面

## 标准方式：用引擎本体创建项目

这是官方推荐的标准流程：**运行引擎本体，在游戏里创建项目**。

在刚才的项目列表底部，有一个"创建新项目"按钮。点它，你可以配置项目名称、项目描述、基于 Deltarune 的哪个章节，以及各章节间的功能开关。随便填一个名字，创建。

创建出来的项目会出现在列表里，点一下就能运行。项目文件存在哪？主菜单里有一个"打开项目文件夹"的选项——点它，资源管理器会打开 mods 目录（源代码版在 `C:\Users\<你的用户名>\AppData\Roaming\LOVE\Kristal\mods\`）。以后你下载、克隆的项目，都放进这个文件夹；放进去的每个文件夹就是一个独立项目。

> 📷 此处插入截图：创建新项目界面 / 项目列表中出现新项目

创建出来的项目里有什么？打开文件夹看看：`mod.json`（项目配置：名称、章节、初始队伍、物品……）、`mod.lua`（项目代码入口）、`assets/`（素材）、`scripts/`（代码）。别急着看懂，第 05 集会一个一个讲。

## 作者的路径：thrash-machine

好了，坦白一下：上面那套标准流程，是官方推荐的做法。但作者本人——也就是我——实际起步用的，并不是它。我用的是自己维护的一个预设模板：[Thrash Machine](https://github.com/Bli-AIk/thrash-machine)。

它和引擎自带的创建方式差别在哪？自带的创建会给你一个非常朴素的空项目；而 Thrash Machine 是一个打包好的起点，默认就带了一些国内开发者会惦记的东西：

- **kristal-i18n 本地化库**：中英文语言文件、游戏内切换语言的设置菜单，开箱即用；
- 一个可运行的 starter 地图和 Dummy 教学战斗，刚装完就有一场战斗可以进；
- 开发期调试工具（终端调试控制台、战斗启动参数）、编辑器配置等一堆预设。

用起来也很简单——把仓库克隆进项目文件夹（就是刚才说的 mods 目录）：

```cmd
git clone --recurse-submodules https://github.com/Bli-AIk/thrash-machine.git
```

克隆完成后，回到 Kristal，项目列表刷新一下，Thrash Machine 应该就出现了。点进去，跑起来：

> 📷 此处插入截图：Thrash Machine 模板运行画面（地图或 Dummy 战斗）

至于"为什么不用标准方式"——说实话就是懒和顺手：标准方式创建的朴素项目，所有东西都要自己重新配一遍；Thrash Machine 一次到位，中文支持、调试工具、构建脚本全都有。而且本系列最终要做的 Dog Battle，就是从 Thrash Machine 衍生出来的（改了 ID、加了狗）。你跟着系列走，用哪个起步都可以——标准方式更"官方"，Thrash Machine 更省事，这条系列接下来用哪个，就是哪个。

## 配置 VSCode

编辑器这一步，官方 wiki 的推荐是 VSCode + 官方扩展，我们照做。

1. 安装 [VSCode](https://code.visualstudio.com/)（安装时建议勾上"添加到 PATH"和"通过 Code 打开"）。
2. 打开扩展面板，搜索 **Kristal**，安装官方扩展（marketplace ID：`kristal.kristal-vscode`）。它是基于 Lua 语言服务器（LuaLS）做的，打开项目时会提示你"是否启用 Kristal 环境"——确认就行。
3. 用 VSCode 打开你的项目文件夹。第一次打开会问"是否信任此文件夹的作者"——这是你的项目，你就是作者，点信任。
4. 现在打开任意 `.lua` 文件，试试输入 `Game.`——应该有 API 补全弹出来。

> 📷 此处插入截图：VSCode 里 Game. 的补全效果

如果扩展没有生效（比如提示没弹出来）：手动安装 Lua 扩展（搜索 Lua，作者是 sumneko，就是 LuaLS 本体），然后在项目设置（`.vscode/settings.json`）里，把 `Lua.workspace.library` 指向你克隆的 Kristal 目录下的 `luadoc_meta` 文件夹，也能得到一样的补全。

## 日常工作流

环境搭好了，之后的日常循环其实就三步：

1. 在 VSCode 里改代码；
2. 终端里（在项目目录）运行 `love .`；
3. 看效果，不满意回到第 1 步。

想再快一点：开发模式下，游戏运行中按 `Ctrl+R` 会快速保存并重新加载项目，改完代码不用重启引擎，按一下立刻生效。

## 常见问题

按经验列几个新手最容易踩的坑：

- **`love` 不是内部或外部命令**：PATH 没配好，或者终端窗口没重新开。重新配置后开新窗口再试。
- **项目不出现在列表里**：确认它直接放在 mods 目录下，且**没有**套在多余的文件夹里（比如把解压出来的双重目录整个扔进去）。
- **点了项目没反应**：如果你放的是别人打包好的游戏，注意"库"（libraries）是不能单独运行的，它们只是给项目用的插件。
- **中文用户名/路径**：Windows 上如果用户名带中文，某些工具链偶尔会闹脾气。能避免就避免，遇到奇怪问题先怀疑这里。
- **版本对不上**：项目 `mod.json` 里有 `engineVer` 字段，比如 `v0.10.0`，要和你的引擎版本匹配。引擎更新了大版本，旧项目可能跑不动。
